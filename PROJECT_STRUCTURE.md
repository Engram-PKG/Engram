# Project Structure

One line per file. Update this alongside any change that adds, removes, or
repurposes a file — treat it as part of the diff, not an afterthought.

## Root

| File | What it is |
|---|---|
| `README.md` | Setup instructions and project overview — start here |
| `ARCHITECTURE.md` | System design, data flow, connector rollout phasing, deployment options |
| `CONTRIBUTING.md` | Branch strategy, commit style, coding standards, the safety-critical confirm-before-action rule |
| `PROJECT_STRUCTURE.md` | This file |
| `docker-compose.yml` | Orchestrates the `db`, `redis`, `backend`, `worker`, `beat`, and `frontend` containers (`frontend` = nginx serving `frontend/` with `nginx/frontend.conf`) |
| `nginx/frontend.conf` | Dev nginx site for the `frontend` container — default static serving plus `Cache-Control: no-cache`, so edited CSS/JS show up on a normal reload instead of a stale cached copy |
| `env.example` | Template for the real `.env` — copy it, never commit the real one |
| `.gitignore` | Excludes `.env`, caches, venvs, and DB volume data from git |
| `.env` | Real secrets/config — gitignored, not committed |

### `backend/app/`

| File | What it is |
|---|---|
| `main.py` | FastAPI entrypoint — CORS setup (exposes `Content-Disposition` so the export download keeps its filename), mounts the `/api/v1` router; sets a Windows-only asyncio event loop policy so psycopg's async driver works outside Docker |
| `core/config.py` | `Settings` — env vars for DB/Redis URLs, secrets, session cookie name, backend/frontend base URLs, OAuth client IDs, Voyage embedding model/dimension, Groq chat model, CORS origins, Groq transcription model, upload size caps (20 MB files / 25 MB audio) |
| `core/security.py` | Password hashing (passlib/bcrypt), JWT session access-token create/decode, OAuth CSRF state-token create/verify |
| `core/crypto.py` | Fernet encrypt/decrypt for connector access/refresh tokens at rest (key derived from `SECRET_KEY`) |
| `db/base.py` | SQLAlchemy declarative `Base` |
| `db/session.py` | Async engine/session factory + the `get_db()` FastAPI dependency |
| `api/deps.py` | `get_current_user` — reads the session cookie, decodes the JWT, loads the user |
| `models/user.py` | `User` table — email, hashed password, optional `full_name`, plus the Settings preferences the chat pipeline reads (`allow_content_in_chat`, `response_tone`, `memory_window_days`); `timezone` (last browser-reported IANA zone, used by background jobs) |
| `models/connector.py` | `Connector` table — one row per (user, provider): encrypted tokens, scopes, expiry |
| `models/memory_item.py` | `MemoryItem` table — one ingested chunk per (user, source, external_id); `embedding` is a 1024-dim pgvector column (Voyage AI); further chunking/LLM enrichment lands later; `occurred_at` is when the item itself happened (drives the timeline), distinct from `created_at` (index time); `upload_id` links chunks to their manual upload; `is_first_chunk()` filters a multi-chunk upload down to one row for browsing/tallies |
| `models/upload.py` | `Upload` table — a manually uploaded file (`kind` = `document`/`voice_note`/`bookmark`, also its memories' `source`): filename, content type, size, sha256 (duplicate guard), deferred original bytes, kind-specific `details`; `UPLOAD_KINDS` |
| `models/conversation.py` | `Conversation` (per-user chat thread: title, `updated_at` bumped per message) and `ConversationMessage` (role, content, citations JSONB, `pending_actions` list (via `pending_actions.message_id`); ordered by identity `seq` since a question and its answer share a transaction timestamp) |
| `models/graph_snapshot.py` | `GraphSnapshot` — the user's last built knowledge graph (JSONB) plus the memory `fingerprint` it was built from; rebuilt only when that changes |
| `models/reflection.py` | `Reflection` — one grounded pattern note: category, tone (positive/neutral/watch), headline, body, tags, `evidence` snapshots of the cited memories, batch id, optional `conversation_id`, `dismissed_at` |
| `models/pending_action.py` | `PendingAction` table — a tool call with a real side effect (`draft_email`, `create_calendar_event`), linked to the reply that proposed it via `message_id`, created `pending`; only a separate confirm request moves it to `executed`/`failed`, or cancel to `cancelled` |
| `schemas/user.py` | Pydantic shapes for `User`: `UserCreate` (optional `full_name`), `LoginRequest`, `UserRead` (incl. name + preferences), and the Settings payloads `ProfileUpdate`, `PasswordChange`, `PreferencesUpdate` (partial — only sent fields change), `AccountDeletion` |
| `schemas/connector.py` | `ConnectorRead` — what `/connectors` returns (never the raw tokens) |
| `schemas/dashboard.py` | `DashboardSummary` — memory counts (total/today/this week/last week/searchable), connected vs available sources, recent activity rows |
| `schemas/memory.py` | `TimelinePage` (items, `next_cursor`, first-page `upcoming` + per-source counts) / `TimelineItem` (title/body split from content, `occurred_at`, `all_day`, source-specific `details`); `SearchResponse` / `SearchResult` (timeline item + match kind + original `url`) / `SearchSuggestions` |
| `schemas/graph.py` | `GraphResponse` — `GraphNode` (you/person/organization/topic with count, first/last seen, per-source counts, keywords, recent memories) and weighted `GraphEdge` |
| `schemas/reflection.py` | `ReflectionRead` (+ `EvidenceItem`), `ReflectionList` (active reflections + memory count, last/next generation, refresh cooldown), `GenerateRequest` (timezone), `DiscussResponse` |
| `schemas/account.py` | `DataSummary` (memories per source with connection state + date span, conversation/message counts) and `DeletedCount` |
| `schemas/chat.py` | `ChatRequest` (message + optional `conversation_id` + the browser's IANA `timezone`; no client-sent history) / `ChatResponse` (reply, citations, `pending_actions` list, conversation id/title) / `Citation`, plus `ConversationSummary`/`ConversationDetail`/`MessageRead`/`ConversationUpdate` for the conversation endpoints |
| `schemas/upload.py` | `UploadRead` — what `/uploads` returns (kind, filename, size, live item count, details; never the bytes) |
| `schemas/actions.py` | `PendingActionRead` — what `/chat/actions/*` returns (id, tool, payload, status, result) |
| `services/chat/retrieval.py` | `search_memories()` — backs the `search_memory` tool: `order="relevance"` embeds the query and does a pgvector cosine search, `order="recent"` sorts by `occurred_at` (when the item happened, not when it was indexed — ingestion runs in batches, so index order tracks nothing real); `source` filter and `limit` (capped at 50) are caller-controlled, not hardcoded; optional `since` enforces the memory window |
| `services/chat/groq_chat.py` | `generate_reply()` — a bounded multi-round (8) tool-use loop: `search_memory` always, plus the app tools of each connected app (`draft_email` for Gmail; the `calendar_tools` set for Google Calendar). Read tools answer immediately; side-effecting tools only ever produce a `PendingAction` draft (null args stripped first so "not given" never means "clear it"). `TurnContext` gives the model the current date/time in the user's timezone, the user's name and which apps are (not) connected, with intent rules (act on casual wording, pick the likely reading, handle every request in a message). The prompt and schemas are kept terse because Groq's free tier caps tokens/minute; the client retries 429s. `generate_title()` writes a short sidebar title, falling back to the message's opening words. `ChatPreferences` applies tone, memory window and content-off mode per turn |
| `services/chat/calendar_tools.py` | Google Calendar chat tools: schemas + `RULES` prompt text; `CalendarSession` (lazily loads the connector token and calendar list once per turn, resolves calendars by id or name); read tools that run live against Google — `list_calendars`, `list_calendar_events` (any date range, all shown calendars merged and sorted, text search, weekday labels and inclusive all-day ends for the model), `find_free_time` (freeBusy minus busy blocks within working hours, weekends skipped unless asked); `prepare_draft()` fetches the target event (and its series for `apply_to='series'`) and builds the create/update/delete/RSVP draft |
| `services/actions/google_calendar_events.py` | Google Calendar API client: live reads (`list_calendars`, `list_events`, `get_event`, `busy_blocks`), draft builders (`build_event_payload` — all-day vs timed, inclusive→exclusive all-day end, 1-hour default, recurrence → RRULE, popup reminders, attendee emails; `build_update_payload` — before/after view + exact PATCH body, moved events keep time-of-day and length, series edits change time of day only; `build_delete_payload`; `build_rsvp_payload`), `can_write()` scope check, and `execute()` — the only path to insert/patch/delete/RSVP, reached exclusively via the confirm endpoint |
| `services/actions/gmail_send.py` | `build_message()` (To/Cc, `In-Reply-To`/`References` threading headers, file attachments, CRLF) and `send_email()` — the only thing that actually calls Gmail's send API (multipart upload endpoint, so attachments up to Gmail's 35 MB fit, with `threadId` so replies stay in their thread); reached exclusively via the confirm endpoint, never from the chat turn itself |
| `services/actions/email_drafts.py` | `prepare_draft()` — turns `draft_email` args into the reviewed draft: validates To/Cc addresses, resolves `reply_to_id` to the original's thread/Message-ID (defaults To to the sender, subject to `Re: …`) and `attachment_ids` to uploaded documents or Gmail attachments (25 MB total cap); `load_attachments()` reads the actual bytes only on confirm (uploads from the DB, email attachments fresh from Gmail) |
| `services/oauth/google.py` | Google OAuth: per-connector scopes (`gmail` — read + send, `google_calendar` — read + `calendar.events` write; connectors granted before write access was added must reconnect), authorize-URL builder, code exchange, refresh, userinfo fetch; `revoke_token()` (best effort, used on disconnect and when deleting a twin/account) |
| `services/oauth/tokens.py` | `get_valid_access_token()` — shared by ingestion and actions: returns the connector's access token, refreshing it first if expired |
| `services/ingestion/base.py` | `NormalizedItem` — the common shape every provider's ingestion module normalizes into (incl. optional `occurred_at`); `parse_email_date()` / `parse_event_start()` date helpers |
| `services/ingestion/gmail.py` | Incremental Gmail sync (`fetch_batch()`): first poll records the `historyId` and backfills `gmail_backfill_days` (≤ `gmail_backfill_max_messages`) one page per poll; every poll replays history since the stored `historyId` (expired history → restart backfill; >200 new messages carry over). Indexes the full body (text/plain, else HTML → text; quoted reply history stripped; capped at 4,000 chars) plus thread/Message-ID/References/To/Cc metadata, skipping drafts/spam/trash/chats. PDF/Word/text attachments are downloaded and chunked as their own `gmail` items (`metadata.kind = "attachment"`, external id `msg:part:chunk`). `occurred_at` from `internalDate`, falling back to the `Date` header. `http_client()` is the single swap point tests mock |
| `services/ingestion/google_calendar.py` | Fetches primary-calendar events from 180 days back to 365 days ahead (paginated, capped at 1000), normalizes title/description/attendees into `NormalizedItem`; `occurred_at` = event start, with an `all_day` flag for date-only events |
| `services/ingestion/documents.py` | `extract_pdf()` (pypdf; empty-password decrypt, PDF creation date), `extract_docx()` (stdlib zip + XML; zip-bomb guard), `decode_text()` (UTF-8, cp1252 fallback), `chunk_text()` — ~2,000-char paragraph-aware chunks with ~200-char overlap |
| `services/graph/entities.py` | `classify_address()` — Gmail `from` / Calendar attendee → person or organization (automated senders by local part/subdomain, grouped by `registrable_domain()`); skips the user's own addresses and calendar resources |
| `services/graph/topics.py` | Topics: spherical k-means (best of fixed-seed restarts) over memory embeddings, TF-IDF-style `cluster_keywords()`, and `llm_labels()` — one Groq call names every cluster from memory titles only, falling back to keyword labels |
| `services/graph/build.py` | `build_graph()` assembles nodes (you, top people/organizations, topics) and weighted edges (you↔node, entity↔topic, co-attendee person↔person); `get_graph()` serves it from `graph_snapshots` unless the memory fingerprint changed (`GRAPH_VERSION` forces rebuilds); `user_addresses()` (the user's own addresses, shared with reflections) |
| `services/search.py` | `hybrid_search()` — keyword (every term must appear in the text, sender, attendees, location or filename) + semantic (query embedding vs memory embeddings, with a calibrated similarity floor/band so gibberish returns nothing) fused by Reciprocal Rank Fusion, upload chunks collapsed; per-process query-embedding cache (the free Voyage tier allows 3 requests/min) and keyword-only fallback when embedding fails; `snippet()` centres on the first match |
| `services/reflections.py` | `generate_reflections()` — last-30-day window (or latest 90 memories) + next-14-day calendar, deterministic FACTS (weekly counts, weekday/hour load in the user's timezone, top senders, upcoming vs previous fortnight), one Groq call for 3–4 reflections as JSON; `parse_reflections()` keeps only well-formed ones citing real memories; `trim_speculation()` cuts "…, indicating/suggesting …" guesses; honours the content-access setting (titles only when off) |
| `services/ingestion/bookmarks.py` | `parse_bookmarks()` — Netscape bookmark export (Chrome/Edge/Firefox/Safari) → http(s) links with folder path and `ADD_DATE`, first occurrence per URL |
| `services/ingestion/voice_notes.py` | `transcribe()` — Groq Whisper transcription; `AUDIO_EXTENSIONS` the endpoint accepts |
| `services/ingestion/uploads.py` | `ingest_upload()` — detect kind (extension + PDF/bookmark sniff; `.docx` via `extract_docx`), per-kind size cap, sha256 duplicate check, extract/transcribe/parse → `NormalizedItem`s (chunk `external_id` = `<upload>:<n>`; bookmarks keyed by URL hash so re-imports upsert), then `store_items()`; all-or-nothing, raises `UploadRejected(status, detail)` |
| `services/ingestion/sync.py` | `sync_connector()` — gets a valid token via `oauth/tokens.py`, calls the provider's fetcher with the connector's `sync_state` and stores the returned cursor in the same commit as the items, embeds only new/changed content (skips unchanged items to save quota), upserts `MemoryItem` rows; writes `occurred_at` when known and never overwrites a stored date with an unknown one. The embed+upsert half is `store_items()`, shared with manual uploads |
| `services/embedding/voyage.py` | `embed_texts()`/`embed_query()` — batches text through Voyage AI's `voyage-4` model (1024-dim, `document` vs `query` input types), off the event loop via `asyncio.to_thread` since the SDK is sync; embeds in slices of 128 texts so big uploads stay under Voyage's per-request limits |
| `api/v1/router.py` | Aggregates every endpoint router under `/api/v1` |
| `api/v1/endpoints/health.py` | `GET /health` — liveness check |
| `api/v1/endpoints/auth.py` | Real signup/login/logout/me — bcrypt hashing, JWT session cookie |
| `api/v1/endpoints/connectors.py` | Real OAuth connect flow for `gmail`/`google_calendar` (list/authorize/callback/disconnect — disconnect revokes the Google grant, keeps synced memories; reconnecting a different account resets `sync_state`); Outlook/Notion/Slack land once their OAuth apps exist |
| `api/v1/endpoints/dashboard.py` | `GET /dashboard/` — per-user stats computed from `memory_items`/`connectors`; activity is derived by grouping `memory_items` per (source, day) plus connector-connected events, since there's no sync log yet |
| `api/v1/endpoints/memory.py` | `GET /memory/timeline` — newest-first feed of past items keyset-paginated on `(occurred_at, id)`, `source` filter + literal `q` substring search (browsing shows one entry per uploaded file; a search shows whichever chunks match), future items returned separately as `upcoming`; `GET /memory/search` (hybrid search with source filter, relevance/newest sort, offset paging, links back to the original email/event/bookmark) and `GET /memory/search/suggestions` (topic/people names from the cached graph, else common title words, plus per-source counts) |
| `api/v1/endpoints/account.py` | Settings backend under `/account`: `PATCH /profile` (name; email change needs the current password), `POST /password`, `PATCH /preferences`, `GET /data`, `GET /export` (JSON download, no secrets/embeddings), `DELETE /memories[?source=]` (forgetting an upload source, or everything, also deletes the uploaded files), `DELETE /conversations`, `POST /reset` (delete twin: revoke Google grants, wipe memories/conversations/actions/connectors, keep login) and `POST /delete` (all that + the user, clears the session) — both password-confirmed; reset/delete also remove reflections, and the export includes them |
| `api/v1/endpoints/uploads.py` | Manual upload under `/uploads`: `POST /` (multipart `file` + optional `occurred_at`; parsed and indexed in-request → 201, or 409 duplicate / 413 too big / 415 unsupported / 422 unreadable / 502 transcription or embedding failure), `GET /` (with live item counts), `GET /{id}/file` (original, always `attachment`), `DELETE /{id}` (file + its memories); 404 for non-owners |
| `api/v1/endpoints/chat.py` | Real RAG chat, persisted per conversation — `POST /` creates a conversation (auto-titled) when no `conversation_id` is given, replays the last 20 stored messages as history, and saves both turns. `GET /conversations`, `GET/PATCH/DELETE /conversations/{id}` list/open/rename/delete threads (404 for non-owners). The model retrieves memories itself via the `search_memory` tool (dedup'd into citations); draft calls come back as `pending_actions` (several per turn allowed), never auto-executed, and are replayed in history so follow-ups can refer to them. `GET/POST /actions/{id}` (`/confirm`, `/cancel`) implement the safety-critical confirm-before-action rule from CONTRIBUTING.md — confirm is the only path that calls `gmail_send.send_email` / `google_calendar_events.execute` (create, update, delete, RSVP; a read-only Calendar grant gets a 400 "reconnect" and the draft stays pending; a confirmed delete also removes that event's memory row). A Groq rate limit becomes a friendly 429 |
| `api/v1/endpoints/graph.py` | `GET /graph/` — the user's knowledge graph built from their memories (services/graph/), cached until the memories change |
| `api/v1/endpoints/reflections.py` | `GET /reflections/` (active list + scheduling state), `POST /generate` (on demand, 10-minute cooldown, stores the browser timezone), `POST /{id}/dismiss` / `/restore`, `POST /{id}/discuss` (opens — or reuses — a chat thread seeded with the reflection and its cited memories) |
| `workers/celery_app.py` | Celery app wired to Redis; a `ping` smoke-test task; the `poll_connectors` beat schedule (every 15 min); `generate_due_reflections` daily beat entry |
| `workers/tasks/connector_sync.py` | `poll_connectors` task — loads every `Connector` id, then syncs each in its own DB session; one connector's bad token or error can't crash or block any other connector's sync in the same batch |
| `workers/tasks/reflections.py` | `generate_due_reflections` task — daily sweep; users with ≥8 memories whose last batch is a week old (or who have none) get a new batch, each in its own session with failures isolated (`only=` scopes it in tests) |
| every other `__init__.py` | Empty — just marks its folder as a Python package |
